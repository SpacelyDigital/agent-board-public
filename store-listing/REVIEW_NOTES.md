## Product description for a final reviewer

Agent Board displays local coding-agent chat status for the installed Codex Mac
app and Claude Desktop’s Code tab. It requires those separate provider apps and
uses their normal local storage locations. General ChatGPT or Claude browser
conversations and unrelated desktop tabs are outside its supported scope.
Provider file formats can change. Unconfirmed states are shown as disconnected
or unavailable instead of implying completion.

The first setup presents native read-only folder choices. The reviewer can
choose the standard Codex and Claude Code source folders in their own test
account. The app requests no Accessibility, Screen Recording, camera, microphone
or Full Disk Access permission for monitoring. Notifications and opening at
login are optional. No app account or developer login is required.

Use the built-in Sample Board to inspect fictional data without connecting a
provider. It must be clearly labeled and must not imply a live account. Sample
provider-open and live notification eligibility remain restricted. Returning
to the live board must preserve the real board and source permissions.

## Data and quotas

User-approved local folders provide titles, identifiers, timestamps, short reply
or permission previews and work status. The board stores review/snooze/display
choices in the recipient’s local container. It does not edit original chats,
submit messages or upload transcripts. The selected Codex index can require a
bounded unnamed private local copy; its source and lifetime limits are disclosed
in the bundled policy. Full transcripts are not copied into the board.

The Store package excludes the direct prototype’s saved-credential, cloud-project
and provider-command readers. Usage displays are cached local observations,
with age and unavailable/stale labels. The optional Claude Code plugin writes
only quota percentages, reset times and observation time to local files. It does
not authenticate or request a model reply. A real five-hour window remains
unverified on the tested account. Cached values cannot certify the active
account or a renewed allowance.

## Optional US support

The app is free and donations unlock nothing. Hidden support is the default
build setting. This candidate explicitly enables `us-external`. Its native
About page uses Apple StoreKit to determine whether a current storefront is USA;
unknown/non-US/unavailable results keep the support section hidden. The native
page rechecks before opening the single fixed Ko-fi page. There is no in-app
purchase flow, donation verification, account synchronization or transaction
lookup. Storefront data is not saved, logged or reported to the developer.
Normal support display and fixed-URL browser handoff were observed once, but
independent country readback, non-US/offline/revocation and final App Review
acceptance remain open. Fake-provider tests remain supporting checks.

The QR is bundled locally, so displaying it contacts no QR or payment service.
A user-chosen browser visit or payment is handled by Ko-fi and may share their
contact/transaction information with Spacely Digital. A chosen support email
opens the mail app without sending or attaching anything automatically. The
privacy text must disclose these voluntary external flows alongside the absence
of automatic developer reporting.

## Final reviewer walkthrough to complete

1. Install the exact final package as an ordinary user. Open all bundled license
   notices and policy pages. Start with no source grants and confirm useful
   unavailable/setup behavior without requesting unrelated access.
2. Use Sample Board and normal keyboard navigation, then return to Live. Grant
   the two provider sources explicitly. Observe real Cooking, input requests,
   Ready, exact-chat handoff and Review/History/Restore without duplicate cards.
3. Forget and regrant a source while monitoring. Verify current counts and
   notifications exclude unavailable sources while Last known content stays clear.
4. Exercise window close/status reopen, Minimize, normal Quit, restart and the
   optional login/notification choices. Verify active completion and a notification
   click reach the same real chat on this exact build.
5. Exercise 200% text and spoken VoiceOver on supported OS versions.
   Measure effects/reduced motion and resource use. Repeat current local-quota
   plugin installation and disclose any missing or stale windows.
6. Test native About/US eligibility using real authorized storefront conditions;
   unknown/offline/non-US must not expose support. Do not make an actual payment
   merely to validate navigation. Confirm mail opens without automatic sending.
